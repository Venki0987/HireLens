Key Design Decisions

Decision Rationale
CrewAI as library (not framework) Full control over web layer, file handling, custom API responses
Sequential agent execution Each agent builds on previous output â€” JD+Resume â†’ Skills â†’ Score â†’ Questions
Raw JSON output (no Pydantic parsing) More reliable with non-OpenAI models that don't support function calling
Dual LLM providers Splits load across Bedrock and Groq to avoid rate limits and reduce latency
Thread offloading (asyncio.to_thread) CrewAI is synchronous; offloading prevents blocking FastAPI's async event loop
LLM-based report generation More flexible than template rendering â€” handles varied agent output formats gracefully
Indeterminate progress bar (not step-based) Honest UX â€” backend doesn't stream per-agent progress, so we don't fake it
